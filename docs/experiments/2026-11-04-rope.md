# RealGPT: classical RoPE vs trainable real RoPE (2026-11-04, CPU)

A tiny side test of the “trainable GyRoPE-real” idea against classical RoPE on
the same memorization/length-generalization scenario.

## What was compared

- RealGPT 64×2, 110,880 params, block 16/32, 3k steps, seeds 0/1.
- **Classical RoPE:** fixed `inv_freq = 1/10000^(...)` (shipped `real.py`).
- **Trainable real RoPE:** one learnable frequency per head/pair, initialised to
  the classical values; same q/k pair-rotation API. 110,944 params (+64).
  This is the real-valued analogue of the GyRoPE-real prototype, not the exact
  historical module; it captures the “learnable positions” axis.

Same 512-char random text and teacher-forced/generation metrics as the
memorization probe.

## Results

| block | RoPE | teacher-forced acc | exact generated prefix |
|---:|---|---:|---:|
| 16 | classical | 0.315 / 0.299 | 26 / 17 |
| 16 | trainable | 0.339 / 0.299 | 16 / 17 |
| 32 | classical | 0.411 / 0.397 | 26 / 24 |
| 32 | trainable | 0.431 / 0.415 | 26 / 23 |

No meaningful difference: the trainable version is within seed noise, fails to
extrapolate past the trained block like classical RoPE, and costs 64 extra
parameters. It does not rescue the RealGPT failure.

## Reading

- This matches the old development result: trainable GyRoPE-real matched
  classical RoPE, did not beat it.
- The memorization advantage is therefore **not** merely “classical positions
  are fixed”. RAT’s relative complex decay/state is doing something different:
  it has no trained-block boundary in this test.
- Caveat: this is a real-valued trainable-frequency analogue, not a bit-exact
  reproduction of the stashed GyRoPE-real (which may use per-head axes/phases).
  A full port could add DOF, but the simple version shows no obvious win.
