# RAT L2 + HyperFormer 11M - partial result (2026-11-01)

The `ratl2-hyper11m` session was cancelled after ~10 h (L2 was still running).
Outputs were saved before cancellation, so both arms are analyzable.

## HyperFormer 11.2M

- 296×9, **8 heads** (head_size 37), level 1, 22k iters / 90.1M chars, lr 3e-4.
- train 1.3158, **val 1.3381**, wall **4.31 h**.
- Compare: RAT 11.24M **1.2684**, RealGPT 11.13M **1.2903**.
- HyperFormer is **0.048 nats worse than RealGPT** and **0.070 worse than RAT** at
  the same parameter count. That is not the historical “30–40 % fewer params and
  still better” pattern; something in this configuration is off.

## RAT L2 12.94M

- Reached **18,000 steps** before the session was cancelled; val 1.3813.

## Old-code check (c3852df)

A detached worktree at `c3852df` (the pre-RAT-integration root-`model.py` tree)
was used to load the old `HyperFormer` and the current one with the *same* state
dict and input. Outputs match to **4.2e-7 max absolute difference** (33,952
params, level 1, block 16). The old `hyper.py` differs from the current one only
by its `ModelConfig` import path; the later `core.py` changes are for level ≥2
(real CD matrix) and GyRoPE interleaving (level ≥2). So the HyperFormer level-1
path did **not** regress during the RAT integration - the 1.3381 result is a
training/config effect, not a rewritten-model bug.

## Suspects for HyperFormer

1. **Head geometry.** Our hyper config has **8 heads × 37 dims**; RAT has
   **37 heads × 8 dims**. Parameter count is identical, but the attention
   geometry is completely different. The historical hyper runs used 8 heads at
   small widths, not 37-dim heads at 11M.
2. **LR.** Historical base was ~4–5e-4; we ran 3e-4. The 0.02 story was a joke,
   but 3e-4 is still below the historical recipe.
3. **Data order.** This run predates the independent data-RNG fix; both arms had
   different batches despite the same seed. The MLflow 11M rerun uses the fix.

Next: rerun HyperFormer 11.2M with **matched heads (37)** at lr 3e-4 and 5e-4,
both with the data-order fix and MLflow. That isolates head geometry from LR
against the existing 8-head/3e-4 result.
