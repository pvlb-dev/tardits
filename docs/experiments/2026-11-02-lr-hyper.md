# Real48 LR probe + HyperFormer 8-head data-order control (2026-11-02)

Both runs used the independent data-order RNG and MLflow. Quota was deliberately
overrun; Kaggle cancelled the 10 h probe at ~8.9 h / 35k steps, but checkpoints
and logs were saved.

## RealGPT 48M LR probe

| arm | lr | steps | train | val | note |
|---|---:|---:|---:|---:|---|
| original | 3e-4 | 22k | 1.5262 | 1.5523 | old global RNG |
| probe A | **5e-4** | 35k | 1.5382 | **1.5476** | +13k steps, no gain |
| probe B | **1e-3** | 34k | 1.8723 | **1.8662** | unstable/worse |

Higher LR does **not** help Real48; 1e-3 is clearly too high, 5e-4 is flat vs the
3e-4 22k run despite 13k extra steps. The “Real is LR-starved” hypothesis is not
supported. If anything the next probe is **lower** LR (1e-4/2e-4), plus a
**3e-4 / 36k** control to separate LR from steps.

## HyperFormer 11.2M, 8 heads, data-order fixed

| arm | lr | val |
|---|---:|---:|
| old (global RNG) | 3e-4 | 1.3381 |
| **data-order fixed** | **3e-4** | **1.2950** |
| data-order fixed | 5e-4 | 1.3128 |

The data-order fix recovers **0.043 nats** for HyperFormer - it now ties RealGPT
11M (1.3253) and is close to RAT 11M (1.2845). The old 1.3381 was largely a
batch-order artifact, not an integration/GyRoPE regression (old/current
HyperFormer level-1 outputs are bit-equal to 4e-7). 5e-4 is worse; 3e-4 is the
better hyper LR.

## Reading

- The 11M architecture ordering after fixing data order: **RAT 1.2845 < Hyper 1.2950 < Real 1.3253** - all within ~0.04 nats, so no strong architecture claim yet.
- Real48 at 35k is still 1.548, far from the 11M arms; extra steps/higher LR don’t close it. The 48M Real is optimization/undertraining limited, not simply LR-starved.
- Old `c3852df` RAT: 1.3703; current code is better.
